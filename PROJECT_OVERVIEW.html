家計ダッシュボード3

夫婦の家計を月単位で集計・可視化するWebアプリ。React SPA を Cloudflare Workers から配信し、 同一 Worker が /api/* を処理する単一ホスト名構成で本番稼働している。 最大の特徴は バックエンドが TypeScript と Python の2言語で二重実装されており、 同じ API 契約・同じロジックを対で保っている点。

Architecture

全体アーキテクチャ

ブラウザ → Cloudflare Access → Worker（Hono）→ D1 という一本道。フロントも同じ Worker が配信する。

🌐 ブラウザ（React 19 SPA）

5つのタブ（ダッシュボード / グラフ / 入力 / 目標 / 設定）を持つ単一ページアプリ。グラフタブは recharts + d3 を引くため lazy() で遅延ロードし、初回バンドルから除外している。

↓ HTTPS

🔐 Cloudflare Access 認証

本番URLは Access で保護。多層防御として、ACCESS_ALLOWED_EMAILS が設定されていれば Worker 側でも Cf-Access-Authenticated-User-Email ヘッダーを検証する。プレビューURL（別ホスト名）は preview_urls = false で無効化し、認証の抜け道を作らない。

↓

⚡ worker/ 本番 TypeScript

Hono on Cloudflare Workers。/api/* のみ Worker が先に処理（run_worker_first）、それ以外は [assets] が frontend/dist を SPA フォールバックで配信。

  • index.ts — 全ルート + 認証ミドルウェア
  • repo.ts — SQLアクセス集約（658行）
  • aggregate.ts / goal.ts — 純関数の集計

🐍 backend/ ローカル専用 Python

FastAPI + uvicorn。ローカル開発・pytest 用のサンドボックス。DB は backend/local.db（stdlib sqlite3）。本番には一切デプロイされない。

  • api/routers/ — 薄いHTTP変換層（7ルーター）
  • src/ — worker/src と同名のロジック本体
  • tests/ — pytest 15ファイル
↓

🗄️ D1 kakei-db 正本

Cloudflare D1（SQLite互換）。これが本番データの正本。backend/data/ のCSVは投入元にすぎず、CSVを直しただけでは本番に反映されない。

💾 backend/local.db

ローカル開発用SQLite。migrations/ は D1 と同一スキーマを共有するため、ローカルと本番でテーブル定義がズレない。

⚠️ 最重要の注意点：バックエンドは2つある
worker/src/repo.ts は backend/src/repo.py の移植であり、両者は同じ API 契約（パス・JSON形状）を提供する。 片方だけ直すと本番とローカルで挙動がズレる。不具合修正・仕様変更は必ずセットで行うこと（対応表は「モジュール解説」参照）。

Database

データベーススキーマ

D1（本番）とローカル SQLite で同一のマイグレーションを共有する。CHECK 制約を積極的に使い、不正な月フォーマットや0円以下の金額を DB 層で弾く設計。

テーブル主なカラム役割・制約
entries id, month, category, amount, source, note, created_at 収入・支出の実績1件。month は GLOB で YYYY-MM 形式を強制、amount > 0。source は manual（手入力・編集可）か import（CSV取込・編集不可）。note は0003で追加された備考欄で、NULLを使わず空文字を既定値にしている。
bundle_items id, kind, month, name, amount サブスク・通信費の項目別明細。kind は subscriptions / communications の2値。(kind, month, name) がUNIQUEなので同月同名の重複を防ぐ。集計時は月ごとの合計が1カテゴリ行として注入される。
category_groups name, sort_order カテゴリの上位グループ（固定費・通信費・変動費など）。表示順を持つ。
categories name, group_name, income_owner, sort_order カテゴリ定義。group_name は外部キー。income_owner は 夫/妻 のみ許可され、収入内訳の集計に使う特別扱いのカテゴリを識別する（＝削除保護の対象）。
goals name, target_amount, source, sort_order 目標（結婚資金・車の買い替え等）。source は savings（貯金ベース）か net_worth（純資産ベース）。
app_settings key, value キーバリューの設定ストア。旧 config.yaml の置き換え先。投資を支出に含めるか（investment mode）やアクティブな目標などを保持。
dashboard_months month ダッシュボードに表示する月の登録簿。データが1件も無い月でも、ここに登録されていれば月セレクタに現れる（＝新しい月を作ってから入力する運用のため）。
